AI 深度用法

把 AI 放进每个待办生命周期，而不是做一个聊天入口。

  • 日记抽任务：保存日记后扫描 “要做、忘了、决定、担心、截止” 句式，给出候选任务，用户逐条确认。
  • 自然语言创建：“下周三提醒我把照片发给小王，每月重复” 解析为 dueDate、reminderTime、recurringType、peopleRefs。
  • 任务拆解：将模糊任务拆成 3-7 个可完成子任务，继承父任务标签和截止日期。
  • 今日排程：综合截止日期、优先级、用户常写作时间、历史完成时段、情绪能量，生成轻重搭配。
  • 习惯联动：现有 linkedTagIds 可以继续用，增强为“日记内容证据 + 标签命中 + 用户确认”的打卡逻辑。
  • 拖延诊断：统计改期次数、过期次数、长时间无子任务、完成耗时，AI 输出阻塞类型和下一步。
  • 复盘回写：任务完成时生成一句完成记录，可写入日记草稿、HabitRecord.summary 或月度挑战日志。

AI 记忆原则

私人日记产品里，AI 的每次“记住”都必须透明。

  • 所有记忆带来源：日记 ID、段落、时间、提取模型、置信度。
  • 人物和关系允许用户合并、改名、删除、禁止再次提取。
  • AI 回答必须引用证据，不确定时说“不知道”。
  • 任务、决策、习惯是行动型记忆，要能回写到待办中心。

同步账户面板

现 Worker 支持手机号 + PIN 登录和最新备份上传下载，但还不足以支撑完整网页端。

登录手机号 + OTP + PIN，PIN 只解锁本地密钥，不直接作为账户唯一凭证。
设备手机、网页、备用设备独立 session，可远程撤销。
备份多版本 manifest，支持增量、冲突、回滚。
加密客户端加密后上传，服务端只存密文、版本、校验和。
审计登录、下载、恢复、AI 访问敏感字段都写 audit log。

Worker 风险修复

这些是上线网页端前必须补的基础。

  • 注册 token：当前注册返回 phone:Date.now()，应统一走随机 token + KV session。
  • CORS：当前 * 过宽，正式 Web 域名应白名单。
  • 备份明文：backup_data 当前直接 JSON 存储，应改密文 blob + manifest。
  • 单版本：上传前删除旧备份，无法回滚，应保留版本链。
  • 设备态：没有 device/session 表，无法管理多端。

总览审查

当前 App 的强项是功能厚度，弱项是产品结构。网页版应先重组心智，再迁移代码。

  • 关键判断：不要把 Android 工具页照搬成 Web 菜单。
  • 第一目标：待办 + AI 做成一个能每天打开的中心。
  • 边界：手机端保留轻操作，网页端负责重整理和 AI 工作流。

待办模块审查

这是最值得优先优化的模块，因为它已经有数据基础，也最容易和 AI 形成实际价值。

  • 现有基础：TodoItem 支持 priority、dueDate、reminderTime、parentId、recurringType、progress、isPinned、linkedTagIds。
  • 现有亮点：autoCompleteHabitsForDiary 已经能通过日记标签自动打卡。
  • 主要缺口：没有任务事件流、AI 结构化变更、项目视图、拖延诊断、复盘沉淀。
  • 建议：先做 AI 待办中心，不要先做泛泛的 AI 聊天升级。

编辑器审查

Android 当前编辑器能力很强，但复杂度集中在 WebView、JS bridge、autosave 和媒体处理。

  • Web 端可以直接做原生富文本，不再绕 WebView。
  • AI 提取候选任务、人物、地点、决策，必须进入确认队列。
  • 草稿保存要使用本地优先策略，避免网络失败导致输入焦虑。

档案审查

时间线、媒体库、统计、搜索应该合并为“可检索档案”。

  • 现有 DAO 已经区分全量 Entry 和 Preview，这是性能方向正确的信号。
  • Web 端要补 FTS、分页、虚拟列表、缩略图懒加载。
  • 所有 AI 检索结果都要能回到原文和原图。

记忆审查

数据库已经埋了人物、决策、向量、挑战等长期能力，适合做成可视化记忆层。

  • 先做证据链和用户修正，再做复杂图谱动画。
  • 记忆实体要支持删除、合并、禁用提取。
  • 待办、决策、挑战之间要互相链接。

同步审查

当前 Worker 是原型级同步服务，不能直接承载完整 Web App。

  • 注册 token 和登录 token 生成逻辑不一致，需要统一。
  • 备份数据应客户端加密，服务端只存密文。
  • 必须增加设备、会话、版本、审计日志。

工程落地审查

建议把这份 HTML 当作 Web 端第一版 PRD + 技术蓝图。

  • P0 只做骨架、待办、Auth，不要一次迁移全部功能。
  • AI 所有写操作走 diff/confirm，避免私人数据被误改。
  • Web 和 Android 共享概念模型，但不共享 UI 代码。
