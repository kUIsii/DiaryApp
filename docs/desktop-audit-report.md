## 1. 主题色调体系 — 关键问题

### 1.1 Android 端主题体系（14 个变体）

| 色系 | Light | Dark | 桌面端对照 |
|------|-------|------|-----------|
| 雾蓝 (Fog Blue) `#6B8DB5` | ✅ | ✅ | ✅ 仅有 Light |
| 苔绿 (Moss Green) `#7BA06E` | ✅ | ✅ | ✅ 仅有 Light |
| 海潮 (Ocean Tide) `#5A9EA0` | ✅ | ✅ | ✅ 仅有 Light |
| 陶粉 (Petal Rose) `#C48880` | ✅ | ✅ | ✅ 仅有 Light |
| 沙金 (Sand Amber) `#B89860` | ✅ | ✅ | ✅ 仅有 Light |
| 陶土 (Clay Paper) `#B89080` | ✅ | ✅ | ✅ 仅有 Light |
| 墨蓝 (Ink Slate) `#4D6AA8` | ✅ | ✅ | ✅ 仅有 Light |

**问题**: 桌面端只有 7 个 Light 变体，完全缺失 7 个 Dark 变体。色值也不完全匹配 Android 端。

### 1.2 色值差异对照

以 雾蓝(Fog) 为例：

| Token | Android (Light) | 桌面端 (current) | 差异 |
|-------|----------------|-------------------|------|
| bg1 | `#F5F7FA` | `#F5F7FB` | 轻微偏差 |
| surface | `#FFFFFF` | `#FFFFFF` | ✅ |
| textPrimary | `#2C3344` | `#2C3344` | ✅ |
| textSecondary | `#5A6577` | `#5A6577` | ✅ |
| accent | `#6B8DB5` | `#6B8DB5` | ✅ |
| accent2 (gradient end) | `#B5926B` | `#B5926B` | ✅ |

**✅ 雾蓝基本一致，但其他主题需要逐项校验。**

### 1.3 Root 默认主题冲突

`styles.css:8-37` 定义了根级 CSS 变量，其中 `--accent: #7C3AED`（紫色），这是默认值，不等于任何主题色。

- 当页面加载但 `body.dataset.theme` 尚未设置时，会出现紫色闪烁
- 应在 HTML 加载前或初始状态就设置默认主题

**修复**: Root 变量的 `--accent` 应该默认为 `fog` 主题色 `#6B8DB5`，或者直接在 `<html>` 标签上设置 `data-theme`。

### 1.4 按钮阴影硬编码紫色

`styles.css:564`:
```css
.btn-primary {
  box-shadow: 0 2px 8px rgba(124, 58, 237, 0.25);
}
.btn-primary:hover {
  box-shadow: 0 4px 16px rgba(124, 58, 237, 0.35);
}
```

`124, 58, 237` 是紫色 `#7C3AED` 的 RGB。在所有主题下都不匹配。应使用 `var(--accent)` 构建 RGBA 阴影，或者在每个 theme 块中覆盖。

### 1.5 侧边栏颜色冻结

`styles.css` 的侧边栏使用固定色：
```css
--sidebar-bg: #1C1917;
--sidebar-text: #D6D3D1;
```

这些颜色不随主题变化。Android 端没有这样的深色侧边栏。应该让侧边栏颜色跟随主题（浅色模式下用浅色背景）。

## 2. 暗色模式缺失

**当前**: 桌面端完全缺失暗色模式。

**Android 端**: 7 个色系 × 2 (Light/Dark) = 14 个完整变体。

**需要增加**: 
- 每个主题的 Dark 变体定义（参考 Android `Color.kt` 中的色值）
- 在设置面板中增加 Light/Dark/跟随系统的切换

--text-secondary-dark: #9AA8C0

### 3.2 字体尺度范围过窄

当前 `--font-scale` 选项: `1`、`1.1`、`1.2`

Android 端的字体系列范围更广：`0.85`~`1.5`

**建议**: 桌面端增加 `0.9`（紧凑）和 `1.3`（超大）选项，以及跟随系统 DPI 的自动检测。

### 3.3 字体一致性

- **Android 端**统一使用 `FontFamily.Serif`（衬线体）正文，非常优雅
- **桌面端**正文使用 `Inter`（无衬线体），标题使用 `Playfair Display`（衬线体）
- 两者不一致，但合理（桌面阅读距离不同），不过可以增加选项让用户选择

## 4. 默认 UI 组件问题

### 4.1 `<input>` 和 `<textarea>` — 默认感仍然明显

即使已经自定义样式，但：

- `input[type="datetime-local"]` 使用了默认的浏览器控件（不同系统表现不一）
- `select` 没有自定义样式（虽然当前未使用）
- 文件输入完全依赖原生控件
- 输入框的 border-color 变化不够明显

**建议参考**:
- https://unicornui.com/ 的自定义表单控件设计
- 使用自定义 datetime 选择器代替原生

### 4.2 颜色变体缺失

当前 `styles.css` 只定义了 `diary-mood` 的 4 种心情色，但 Android 端定义了 9 种心情色。进度条、热力图等组件也没有对应的颜色定义。

### 4.3 字体堆栈不安全

```css
--font-heading: 'Playfair Display', Georgia, serif;
```

Playfair Display 需要从 Google Fonts 加载，如果在无网络环境（离线）时无法加载。应增加 fallback 并考虑将字体打包到安装包中。

## 6. 布局与交互 Bug

### 6.1 响应式布局缺陷

```css
@media (max-width: 768px) {
  .sidebar { width: 60px; }
  .nav-item span:not(.nav-icon) { display: none; }
}
```

- 最小宽度 60px 的侧边栏在 >768px 时无法调整，浪费空间
- 没有处理 768-1024px 之间的过渡
- 任务三栏布局在中等屏幕会过于拥挤

**修复**:
- 增加可折叠侧边栏（带展开/收起按钮）
- 增加中等屏幕 (768-1024px) 的两栏任务布局
- 侧边栏应该可拖拽调整宽度

### 6.2 Overflow 截断问题

`.main-body` 设置了 `overflow-y: auto`，但某些 view 的内容可能被截断，尤其是当 header + sidebar 高度大于视口时。

**检查方法**: 缩小窗口高度，确认所有 view 的底部内容可滚动到。

### 6.3 Toast 定位

Toast 使用 `position: fixed` + `bottom: 24px; right: 24px`。但如果内容很长（如错误信息），toast 会被截断。应设置 `max-width` 和 `word-break`。

### 6.4 Diary Modal 无背景滚动锁定

当显示日记 modal 时，背景内容仍可滚动。应该增加 `overflow: hidden` 到 body。

### 6.5 任务卡片 hover actions

`.task-actions` 默认 `opacity: 0`，hover 时显示。但在触屏设备上（如果有人在触屏本上使用），hover 状态不存在，删除按钮永远不可见。

**修复**: 在 touch 设备上保持可见，或增加点击展开。

### 6.6 同步状态无自动刷新

同步完成后没有自动定时检查状态，需要手动点击"立即同步"。应该增加：
- 启动时自动同步
- 每 2 小时自动后台同步（同 Android 端）
- 同步计时器显示

### 6.7 无全局快捷键

桌面应用没有快捷键说明。需要支持：
- `Ctrl+N` 新建待办
- `Ctrl+K` 搜索
- `Ctrl+Shift+D` 新建日记
- `Ctrl+,` 打开设置
- `Escape` 关闭 modal/planner

## 8. 互通同步审查

### 8.1 当前实现

✅ 手机号 + PIN 登录/注册（调用 Workers API）
✅ 数据打包推送（tasks + diaries + aiDrafts + archive）
✅ 多端数据合并
✅ 账号状态持久化

### 8.2 缺失项

- ❌ **无数据拉取功能**: 仅有推送 (`syncWithCloud` 只有 `POST /api/backup`)，没有从云端拉取
- ❌ **无冲突检测**: 多端同时修改时可能冲突
- ❌ **无同步进度条**: 大数据量同步时无反馈
- ❌ **无自动定时同步**: 没有定时器自动执行 sync
- ❌ **断开后状态不清除**: 只清 token 不清除数据

### 8.3 修复方案

1. 增加 `GET /api/backup` 拉取云端数据，合并到本地
2. 增加 `lastSyncAt` 时间戳对比，实现增量同步
3. 增加同步进度 UI
4. 增加 `setInterval` 每 2 小时自动同步
5. 增加断开时可选"保留本地数据"或"清除同步数据"
