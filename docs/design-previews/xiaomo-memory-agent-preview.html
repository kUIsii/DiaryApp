02 / Product Shape

它的核心不是更聪明，而是更连续。

小墨 2.0 的体验重心是“同一性”：同一个人格、同一段关系、同一套记忆边界。工具调用和周报都要服务于这个连续性，而不是把它变成另一个任务管理机器人。

Persona Card从喜欢的对话提炼，不强迫用户写提示词。可以编辑、回滚、设为默认。
Memory Bank事实、偏好、关系、事件、目标分开存。每条记忆有来源和可信度。
Xiaomo Inbox主动留言先进入 App 内信箱，系统通知只用于真正值得打断的内容。

03 / Data Flow

一次聊天请求应该这样组装。

1读取默认人格卡和用户确认过的风格偏好。
2读取当前对话摘要和最近 10-20 条消息。
3按用户问题检索相关记忆、日记片段、待办状态。
4把可用工具作为受限能力列表提供给模型。
5模型给出回复或操作意图，App 决定是否展示确认卡。

04 / Safety

让小墨活起来，但不要失控。

主动性必须有节制：低频、可关闭、可解释、可删除。它可以观察和建议，但不能伪造记忆，不能替用户做高风险决定，不能在未确认时修改日记或删除数据。

7 主题适配矩阵

不强行替换现有主题，而是给每个主题配一套“卡片装饰规则”：同一功能在不同主题里换边条、纸张、印章和阴影。

纯净浅纸纸纹、浅阴影、细网格，适合默认日记阅读。
深色墨蓝减少大面积发光，用细边框和低亮色签强调层级。
森林绿适合习惯、恢复、长期目标，卡片可用植物感边签。
海盐青适合清爽整理、同步状态、周计划和轻工具入口。
玫瑰粉适合情绪接住、私密留言、关系记忆，但要控制甜度。
琥珀暖适合复盘、成就感、晚间回顾，票据感会更自然。
薄紫鸢尾适合人格卡、灵感箱、梦境记录，保留一点神秘感。

一条更真实的使用周期

这部分不是功能列表，而是把小墨从“第一天接入”到“几个月后成为固定陪伴”的节奏排出来。每个阶段都可以独立开发和验证。

Day 0

保存喜欢的小墨

用户从第 5 个对话里点“这个小墨很对”。系统提炼人格卡，生成风格锚点，让新对话继承这份语气。

Day 1

新对话不再重开人格

新建对话时，小墨仍知道用户不喜欢客服腔，也知道要先接住情绪，再把行动缩小。

Week 1

长聊开始自动整理

对话超过阈值后生成滚动摘要。旧消息仍保留，但每次请求只带摘要、近期消息和相关记忆。

Week 2

第一份周回顾

小墨把日记、待办、习惯串起来，生成一份有语气的周报，并提供可确认的下周待办草稿。

Month 1

记忆开始可管理

用户可以查看“它记住了什么”，删除不准的记忆，修正人物、偏好、表达边界。

Month 3+

成为日记的连续意识

小墨能在旧日记、新待办、习惯断点之间发现线索，但仍保持克制，只在合适时留言。

第一期，先稳定灵魂

  • 新增 Persona Card 数据模型和设置入口。
  • 从指定对话提炼人格，支持设为默认。
  • 对话收藏、搜索、摘要和长聊压缩。
  • 每次 AI 请求统一走 Context Builder。
  • 保留现有聊天 UI，但加入人格状态提示。

第二期，再让它行动

  • 建立 Memory Bank，分事实、偏好、关系、事件和目标。
  • 加入工具调用意图解析和确认卡。
  • 接入日记检索、待办查询、周报生成。
  • 新增小墨信箱，承载主动留言和报告。
  • 用 WorkManager 做低频后台观察，不追求常驻在线。

视觉说明：这个预览采用浅色纸张网格、倾斜便签和柔和混色渐变，参考 shadergradient.co 的浅色动态混合氛围，并收敛到 DiaryApp 更适合长期阅读的温柔低对比风格。 页面为静态 HTML 原型，主要用于确认小墨长期记忆、主动陪伴和工具确认的产品感觉。
