编辑器迁移方案

Quill.js 的 IME/光标问题反复出现，评估并规划编辑器迁移方案。对比 TipTap、Aztec、compose-rich-editor 等替代方案。

当前问题 方案对比 推荐方案 迁移步骤

当前 Quill.js 问题

基于最近 15+ 个修复提交的分析，Quill.js 存在以下持续性问题。

问题 频率 影响 根本原因
IME 输入法冲突 高 中文输入时内容丢失/重复 Quill 的 composition 事件处理不完善
光标定位异常 高 光标跳转到错误位置 WebView 和 Quill 的光标同步问题
滚动行为不稳定 中 编辑时自动滚动异常 WebView 内部滚动和外部滚动冲突
Enter 键行为 中 换行行为不符合预期 Quill 的块级元素处理

方案对比

三种主要替代方案的详细对比。

check_circle TipTap 推荐

基于 ProseMirror 的现代化编辑器框架。扩展性强，社区活跃。

优势

  • ProseMirror 内核，IME 支持好
  • 扩展系统完善，易于定制
  • TypeScript 支持，类型安全
  • 社区活跃，文档完善
  • 支持 Markdown 快捷键

劣势

  • 需要 WebView 环境
  • 包体积较大 (~200KB)
  • 需要自定义 Delta 转换

text_fields Aztec

WordPress 开发的原生 Android 富文本编辑器。基于 EditText。

优势

  • 原生实现，无 WebView
  • IME 支持完美
  • 性能优秀
  • WordPress 团队维护

劣势

  • 功能相对简单
  • 自定义扩展困难
  • 需要数据迁移
  • Kotlin/Java 学习成本

code compose-rich-editor

Jetpack Compose 原生富文本编辑器。纯 Compose 实现。

优势

  • 纯 Compose 实现
  • 与现有 UI 完美集成
  • 无 WebView 依赖

劣势

  • 功能不完善
  • 社区较小
  • 生产环境风险高
  • 复杂格式支持有限

推荐方案: TipTap

基于综合评估，推荐使用 TipTap 作为 Quill.js 的替代方案。

评估维度 Quill.js (当前) TipTap Aztec
IME 支持 差 好 完美
扩展性 中 优秀 中
数据迁移 - Delta 兼容 需要迁移
维护成本 中 低 中
学习曲线 - 低 中

建议：短期（1-2周）先升级到 Quill 2.0 看是否解决问题。中期（1-2月）评估 TipTap 迁移。长期（3-6月）考虑 Aztec 原生方案。

TipTap 迁移步骤

从 Quill.js 迁移到 TipTap 的详细步骤。

步骤 任务 工作量 风险
1 引入 TipTap 依赖，创建 editor.html 1天 低
2 实现 Delta JSON → TipTap JSON 转换器 2天 中
3 重写 DiaryJsBridge 适配 TipTap API 1天 低
4 测试所有格式（粗体/斜体/列表/代码块/图片） 1天 低
5 测试 IME 输入（中文/日文/韩文） 1天 中
6 数据迁移工具（批量转换已有日记） 1天 中
7 灰度发布，收集用户反馈 1周 低
