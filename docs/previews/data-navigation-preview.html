问题与优化 Issues & Optimization
当前问题: 直接 DAO 调用
ViewModel 直接调用 Room DAO，缺少 Repository 抽象层。数据源逻辑分散在各 ViewModel 中，导致：
- 缓存策略无法统一管理
- 数据源切换 (本地/远程) 需逐处修改
- 单元测试难以 mock 数据层
- 业务逻辑与数据获取耦合
建议: 统一 Repository + UseCase 模式
引入 Repository 模式封装数据访问，UseCase 封装业务逻辑：
- DiaryRepository 统一管理日记 CRUD
- HabitRepository 管理习惯与打卡
- UseCase 处理跨实体业务 (如日记+标签+心情)
- 便于后续接入云同步 / 数据迁移
当前问题: 手动导航管理
使用自定义状态机管理页面切换，存在以下问题：
- 深层链接 (Deep Link) 支持困难
- 页面转场动画不统一
- 返回栈逻辑需手动维护
- 参数传递缺乏类型安全
建议: 迁移至 Navigation Compose
采用 Jetpack Navigation Compose 重构导航：
- NavHost + composable() 声明式路由
- 路由参数类型安全 (Kotlin Serialization)
- 内置返回栈管理与动画支持
- 便于实现底部导航栏 + 侧边栏布局
当前问题: WebView Bridge 数据序列化开销
编辑器每次保存需将整个 Delta JSON 通过 JS Bridge 序列化传输，大文档场景下存在性能瓶颈。建议：增量同步 (仅传输变更部分)、防抖策略优化 (当前 500ms)、大文档分片存储。
当前问题: 8 张表缺乏统一 Migration 策略
随着实体增多，Room Migration 脚本管理变得复杂。建议：引入 Migration 测试、版本化 Schema 导出 (Room Schema Location)、考虑 AutoMigration 支持的场景。
