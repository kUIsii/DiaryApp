重构建议
抽取公共 Repository 层
当前各模块直接访问 Room DAO，导致数据层耦合度过高。建议抽取统一的 Repository 接口层，各模块通过依赖注入获取数据服务，降低对具体数据库实现的依赖。
预期影响: 高 -- 可降低数据层耦合度约 40%
统一事件总线
模块间通过 LiveData/Flow 直接观察彼此状态，形成隐式依赖。引入统一事件总线（如 SharedFlow 封装），解耦模块间通信，使依赖关系显式化、可追踪。
预期影响: 高 -- 消除首页与编辑器间的双向耦合
模块化 Navigation
当前导航逻辑分散在各模块中，页面跳转硬编码目标路由。建议采用 Navigation Component 模块化方案，各模块声明自己的路由契约，通过 DeepLink 解耦页面间跳转。
预期影响: 中 -- 改善首页/待办模块的路由耦合
共享 UI 组件库
多个模块存在重复的卡片、列表项、输入框等 UI 组件。抽取为独立的 Compose 组件库，统一设计语言，减少代码重复，同时降低模块间的视觉耦合。
预期影响: 中 -- 减少约 30% 的重复 UI 代码
