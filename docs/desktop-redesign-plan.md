## 一、桌面端 vs 移动端 — 核心差异

### 桌面端的独特优势（应该利用）

| 优势 | 可以做什么 |
|------|-----------|
| **大屏幕** | 多面板同时展示（笔记+AI+日历）、信息密度高、仪表盘 |
| **键盘 + 鼠标** | 快捷键驱动、精准拖拽、批量操作、右键菜单 |
| **常驻运行** | 全局热键即时唤出、系统托盘、后台同步 |
| **文件系统** | 拖拽附件、导入导出、本地备份 |
| **多窗口** | 独立弹窗、分屏工作 |
| **无电量焦虑** | 持续动画、实时分析、大文件处理 |
| **性能更强** | 复杂图表、数据挖掘、跨年分析 |
| **创作场景** | 全屏写作、AI 辅助、长文编辑 |

### APP 端适合但桌面端不该抄的功能

| APP 功能 | 为什么桌面不该做 | 替代方案 |
|---------|----------------|---------|
| 日历 | 手机看日历是高频场景，桌面谁开个应用看日历？ | **时间线 + 热力图 + 甘特图** |
| 环境音/白噪音 | 桌面有 Spotify/YouTube | 专注模式集成 |
| 健康数据 | 桌面没有传感器 | **写作健康（字数/时长/节奏）** |
| 地点标记 | 桌面的地点信息没有意义 | **项目/领域标记** |
| 时间胶囊 | 手机开胶囊有仪式感，桌面太正经 | **里程碑回顾 + AI 时间线** |
| 成就系统 | APP 端解闷用，桌面端不需要游戏化 | **写作统计 + 成长轨迹** |
| 应用锁/PIN | 桌面有 OS 锁屏 | **加密存储敏感日记** |
| 截图保护 | 桌面不需要 | 不需要 |
| 倒数日 | 谁会打开桌面应用看还剩几天？ | **deadline 看板** |
| Widget | 桌面没有 widget 概念 | **系统托盘 + 通知** |
| 语音备忘录 | 桌面有麦克风但场景少 | 可做可不做 |

## 二、当前版毁灭性审查

### 2.1 一句话总结

> 当前版本是一个 **Web 移动端界面缩小后框在 Electron 窗口里** 的东西，完全没有利用桌面端的任何优势。

### 2.2 "要你何用"清单

| 当前元素 | 问题 | 还留吗 |
|---------|------|--------|
| 日历月视图 | 桌面端完全不会有人为了看日记记录去点日历格子 | ❌ 重构为时间线热力图 |
| 统计 6 个卡片 | 就 6 个数字，连个趋势都没有 | ❌ 改为仪表盘 |
| 日记 modal | 写日记弹个框？桌面端需要全屏书写空间 | ❌ 改为全屏编辑器 |
| 任务三栏 Inbox/Today/Planned | 想法是好的但执行力太差，无法拖拽 | 🟡 保留但强化 |
| AI 聊天在主体区域 | 占一整块区域，但桌面端最适合的是侧边 AI | ❌ 改为侧边面板 |
| 侧边栏固定 240px | 不能拖拽不能折叠 | ❌ 可折叠 + 可拖拽 |
| 设置页面 | 功能太少，字体缩放才 3 档 | 🟡 扩充 |
| 同步页面 | 逻辑正确但 UI 太寒碜 | 🟡 保留 |
| 整体字体 | 41 处过小，桌面端 27 寸显示器看蚂蚁字 | ❌ 全部重写 |
| 颜色系统 | 7 个主题都只有 light，默认还是紫色 | ❌ 全部重写 |
| 日记列表 | 没有分页、搜索、筛选、无限滚动 | ❌ 重写 |
| 任务列表 | 没有搜索、批量、拖拽、子任务 | ❌ 重写 |
| AI 聊天 | 规则引擎太弱，大屏聊天体验粗糙 | ❌ 重写 |

### 2.3 代码质量

见上一轮报告的 **【一】逐函数代码缺陷清单**，问题依旧。核心是：

1. `renderer.js` 一个文件 915 行 — **必须拆**
2. `styles.css` 一个文件 1768 行 — **必须拆**
3. 所有 view 全部预渲染在 HTML 里，用 `display:none` 切换 — **必须改**
4. `renderAll()` 每次全部重绘 — **必须改**

## 三、UI 视觉重构方案

### 3.1 整体风格

```
风格: 精致极简主义 + 微妙动效
参考: Linear.app / Notion / iA Writer 的桌面感
色调: 从 Android 端继承 7 色调色板 (fog/moss/ocean/petal/sand/clay/ink)
      但桌面端增加 Dark 变体
字体: 
  界面: Inter (保留，增加字号)
  标题: Playfair Display (保留)
  书写: 新增等宽/衬线切换选项 (写日记时的字体)
```

### 3.2 布局革命：从"单页"到"桌面工作室"

当前: 侧边栏 + 主内容区（类似手机 app 放大版）

目标:
```
┌──────────────────────────────────────────────┐
│  菜单栏  File  Edit  View  Tools  Help       │
├──────┬───────────────────────────────────────┤
│      │  Toolbar (搜索 + 快捷操作 + 同步状态)   │
│  Side├───────────────────────────────────────┤
│  bar │                                       │
│      │   主工作区 (可拆分多面板)               │
│  Nav │                                       │
│  +   │  ┌──────────┬──────────┬──────────┐   │
│  Tray│  │ 日记列表  │ 编辑器    │ AI 侧边  │   │
│      │  │          │          │          │   │
│      │  └──────────┴──────────┴──────────┘   │
│      │                                       │
├──────┴───────────────────────────────────────┤
│  状态栏 (字数/同步/快捷键提示)                │
└──────────────────────────────────────────────┘
```

### 3.3 统一设计语言

**圆角体系**:
- 小元素 (tag/chip): 6px
- 常规卡片/按钮: 10px
- 大卡片/面板: 16px
- Modal/弹窗: 24px
- 圆角按钮/toggle: 9999px

**阴影体系**:
```
--shadow-sm: 0 1px 3px rgba(0,0,0,0.06)
--shadow-md: 0 4px 12px rgba(0,0,0,0.08)
--shadow-lg: 0 8px 30px rgba(0,0,0,0.12)
--shadow-xl: 0 20px 60px rgba(0,0,0,0.15)
```
所有阴影使用 `color-mix(in srgb, var(--accent) 15%, rgba(0,0,0,0.1))` 来带有主题色倾向。

**动画体系**:
```
--duration-instant: 0ms
--duration-fast: 100ms
--duration-normal: 200ms
--duration-slow: 350ms
--ease-out: cubic-bezier(0.22, 1, 0.36, 1)
--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1)
```

### 3.4 背景系统

参考 shadergradient.co 的动态渐变:

```css
body {
  background: 
    radial-gradient(circle at 20% 15%, color-mix(in srgb, var(--accent-bg) 60%, transparent) 0%, transparent 40%),
    radial-gradient(circle at 80% 85%, color-mix(in srgb, var(--accent-bg) 30%, transparent) 0%, transparent 35%),
    var(--bg);
}
```

每个主题的 accent-bg 不同，背景的微妙渐变也会随之变化。

## 四、功能矩阵：砍掉什么 + 新增什么

### 4.1 要砍掉/替换的功能

| 当前功能 | 处置 | 替代方案 |
|---------|------|---------|
| 日历月视图 | ❌ 砍掉 | 热力图 + 时间线（见下文） |
| 统计页面 6 卡片 | ❌ 砍掉 | 仪表盘（见下文） |
| 日历详情区域 | ❌ 砍掉 | 时间线集成 |
| chat 占主体 | ❌ 改为侧边 | AI 侧边面板 |

### 4.2 要保留但彻底重写的功能

| 功能 | 保留原因 | 重写方向 |

| AI 助手 | 桌面端大屏+键盘输入更适合聊天 | 侧边面板、流式输出、上下文 |
| 互通同步 | 跨设备同步是核心价值 | 双向 + 自动 + 可视化 |
| 设置 | 桌面端需要更多配置项 | 增加快捷键/主题/存储管理 |

## 五、21 个桌面原生功能详细设计

### P0-1: 多面板工作区

```
┌─────────────┬──────────────────┬─────────────┐
│  面板 A     │  面板 B (主)      │  面板 C     │
│             │                  │             │
│ 日记列表    │  日记编辑器       │  AI 侧边    │
│ 或任务列表  │  或任务看板       │  或提示     │
│             │                  │  或日历     │
│ 可拖动宽度  │                  │  可收起     │
└─────────────┴──────────────────┴─────────────┘
```

- 最多 3 面板
- 每个面板可以独立选择内容类型
- 面板宽度可拖拽调整
- 面板 C 默认是 AI 侧边，可收起
- 类似 VS Code 的编辑器组概念

**实现**: CSS Grid + ResizeObserver + localStorage 保存布局

### P0-2: Markdown 全屏编辑器

**设计参考**: iA Writer / Typora / Notion

```
┌─────────────────────────────────────────────┐
│ ← 返回列表  日记标题 [可编辑]   💾 自动保存   │
├─────────────────────────────────────────────┤
│  ┌───────────────────────────────────────┐  │
│  │ ## 今天做了什么                        │  │
│  │                                       │  │
│  │ 今天终于把设计定稿了。用了 **Figma**   │  │
│  │ 的自动布局，效率提高了不少。           │  │
│  │                                       │  │
│  │ - [ ] 提交设计稿给客户                │  │
│  │ - [ ] 写周报                          │  │
│  │                                       │  │
│  │ > 一句值得记住的话                    │  │
│  └───────────────────────────────────────┘  │
│  字数: 342  心情: 😊  标签: #工作 #设计     │
├─────────────────────────────────────────────┤
│  工具栏: B I H1 H2 | 图片 | 待办 | 模板     │
└─────────────────────────────────────────────┘
```

**特性**:
- Markdown 原生输入（所见即所得或分屏预览）
- 自动保存 (debounce 2s)
- 字数统计 + 预计阅读时间
- 心情选择器（不占空间的 dropdown）
- 标签 inline 编辑
- 插入图片（拖拽 / 粘贴剪贴板）
- 自动生成任务（从 - [ ] 创建待办）

### P0-3: 任务看板 (Kanban)

```
┌──────────────┬──────────────┬──────────────┬──────────────┐
│  📥 Inbox   │  📋 待办     │  🔄 进行中   │  ✅ 已完成   │
│              │              │              │              │
│  🟡 买牛奶   │  📐 设计稿   │  🔵 写周报   │  🟢 回复邮件 │
│  📝 整理书桌 │  🔴 项目A   │  🟡 改bug    │  🟢 开会     │
│              │              │              │              │
├──────────────┴──────────────┴──────────────┴──────────────┤
│  列表视图切换 | 筛选: 全部/今天/本周/标签                  │
└───────────────────────────────────────────────────────────┘
```

**与手机端的不同**:
- 拖拽跨列移动任务
- 键盘快捷键 (1-4 快速移动到某列, Enter 编辑, Del 删除)
- 多选 + 批量移动/删除
- 同时显示看板 + 列表两种视图
- 可自定义列名称和数量

### P0-4: 全局搜索 (Ctrl+K)

```
┌─────────────────────────────────────┐
│  🔍 搜索任务、日记...          ⌘K   │
├─────────────────────────────────────┤
│  最近搜索                           │

│    🔵 完成设计稿定稿               │

- `Ctrl+K` 或 `Cmd+K` 唤出

- 结果按类型分组（任务/日记/标签）
- 键盘上下选择 + Enter 跳转
- 支持自然语言日期筛选（"上周的任务"）

### P0-5: 系统托盘 + 全局热键

```
系统托盘图标: 📝 (应用图标)

  │  快速添加待办    │  ← 弹出输入框

**全局热键**:
- `Alt+Space` / `Ctrl+Shift+D`: 唤出快速记录窗口
- `Ctrl+Shift+T`: 快速添加待办
- `Ctrl+Shift+F`: 全局搜索

**实现**: `electron-tray` + `globalShortcut`

### 7.2 图表实现方案

使用 **纯 SVG**（无第三方库依赖）:
- 折线图: `<polyline>` + 坐标轴
- 柱状图: `<rect>` 数组
- 环形图: `<circle>` stroke-dasharray
- 热力图: `<rect>` 网格 + 颜色映射

**为什么不用 chart.js / d3**: 桌面端数据量不大（每月几十条），SVG 直接渲染更轻量、更可控、无依赖。

## 总结：Desktop First 设计原则

1. **不抄 APP 功能** — APP 的日历、环境音、成就等不搬到桌面
2. **发挥大屏优势** — 多面板、仪表盘、时间线、热力图一目了然
3. **键盘驱动** — 全局搜索 (Ctrl+K) + 快捷键体系是第一优先级
4. **拖拽一切** — 看板拖拽、面板拖拽、文件拖拽
5. **持久化** — 系统托盘常驻 + 后台同步 + 自动保存
6. **数据可视化** — 用 SVG 图表代替数字卡片
7. **写入体验优先** — 全屏 Markdown 编辑器、自动保存、专注模式
8. **互通而非复制** — 与 APP 端共享数据，但交互完全不同
