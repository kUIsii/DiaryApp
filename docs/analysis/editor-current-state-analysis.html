架构分析

编辑器采用 WebView + Quill.js 的混合架构，通过 JavaScript Bridge 实现 Kotlin ↔ WebView 通信。

architecture WebView 架构

  • Quill.js 编辑器 - 在 WebView 中运行的富文本编辑器
  • Delta JSON 格式 - 内容存储为 Quill Delta 格式
  • JS Bridge - DiaryJsBridge 处理双向通信
  • 本地文件 - editor.html 从 assets 加载

sync 通信流程

  • Kotlin → JS - evaluateJavascript() 调用 Quill API
  • JS → Kotlin - JavascriptInterface 回调
  • 内容同步 - 定时/事件触发 Delta JSON 导出
  • 主题同步 - setTheme() JS 调用

关键发现：EditorScreen.kt 有 1639 行，是整个应用中最大的文件。它包含了太多职责：标题输入、WebView 配置、工具栏、元数据编辑、草稿管理、预览模式等。应该拆分为多个 smaller Composable。

问题诊断

当前编辑器模块存在的主要问题，基于最近 15+ 个修复提交的分析。

warning 已知问题 (高频修复)

  • 光标定位 - 多次修复光标跳转、光标 docking 问题
  • 键盘冲突 - IME 输入法与 WebView 的交互问题
  • 滚动行为 - 编辑时自动滚动到光标位置不稳定
  • 内容丢失 - 快速输入时内容可能丢失

info 架构问题

  • 文件过大 - 1639 行单文件，难以维护
  • WebView 生命周期 - stopLoading/destroy 顺序敏感
  • Base64 开销 - 内容传输使用 Base64 编码，增加延迟
  • 主题闪烁 - 深色模式切换时有可见闪烁

优化建议

按优先级排序的改进方案。

P0 拆分 EditorScreen

将 1639 行的 EditorScreen 拆分为：EditorHeader、EditorContent、EditorMetadata、EditorDrafts 等 smaller Composable。每个组件 200-300 行。

预计工作量: 2天 | 影响: EditorScreen.kt

P0 评估编辑器迁移

Quill.js 的 IME/光标问题反复出现。评估迁移到 TipTap (ProseMirror) 或 Aztec (原生) 的可行性。短期可尝试 Quill 2.0。

预计工作量: 评估 1天 + 迁移 5-10天

P1 HTML 缓存字段

在 DiaryEntry 中新增 cachedHtml 字段，保存时自动生成。详情页直接使用缓存 HTML，避免每次 Delta→HTML 转换。

预计工作量: 1天 | 影响: DiaryEntry + Editor + Detail

P1 统一 WebView 配置

Editor 和 Detail 都使用 WebView，但配置代码重复。抽取 DiaryWebViewFactory 统一管理 WebView 初始化、JS Bridge、主题设置。

预计工作量: 1天 | 影响: Editor + Detail

P2 自动保存优化

当前使用 debounce 保存策略。可优化为：仅在内容实际变化时保存，使用 Diff 算法减少不必要的写入。

预计工作量: 0.5天 | 影响: EditorViewModel

P2 离线编辑支持

支持在无网络环境下编辑（当前 Quill.js 从本地 assets 加载，已基本支持）。确保图片插入等操作不依赖网络。

预计工作量: 0.5天 | 影响: Editor
