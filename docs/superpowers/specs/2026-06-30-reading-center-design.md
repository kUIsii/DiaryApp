# 阅读中心重设计

## 目标

把工具区中的 `沉浸阅读 / 专注模式 / 大纲视图 / 封面主题` 从四个彼此独立的阅读工具，升级为一个真正可持续使用的 `阅读中心`。

这次重设计的重点不是单纯增加功能点，而是把阅读体验组织成一条稳定可重复的闭环：

1. 进入阅读前，快速找到值得继续读的内容
2. 在阅读中保持沉浸、专注和视觉一致性
3. 在需要时切换到专注模式而不丢失当前阅读上下文
4. 读完后回看结构、主题和重点段落
5. 把视觉主题、阅读偏好和最近进度沉淀成长期可复用的阅读空间

## 现状问题

当前这组能力并不弱，但整体仍然是“阅读工具集”，还不是“阅读中心”，主要问题如下：

- `沉浸阅读` 已经有翻页、字体、暖光、深色和阅读计时，但仍然更像简单的日记翻页器，没有书签、继续阅读、最近进度、目录入口和读后动作。
- `专注模式` 已经是一个完整计时器，但和当前阅读内容没有关系，用户进入后会失去“我正在读哪篇、为什么要专注、结束后回到哪里”的上下文。
- `大纲视图` 信息量很大，甚至已经具备单篇结构、时间范围分析、主题分析、AI 标签和可视化统计，但在交互上更像分析后台，不像阅读辅助层。
- `封面主题` 已经有预设、自定义、AI 推荐和使用统计，但它服务的是“封面设置”，不是“阅读空间”，用户无法直接看到主题切换如何影响真实阅读页。
- `工具页` 的阅读分区只是并列入口清单，没有“继续阅读”“最近阅读”“推荐动作”这样的中心化主入口。
- 这四页各自维护自己的状态，缺少统一的 `阅读会话`，导致页面跳转时上下文断开。

## 设计原则

- 阅读体验优先，不能为了功能密度牺牲阅读节奏。
- UI 设计要明显提升，重点优化层级、留白、标题节奏、正文排版和控件密度。
- 功能必须真实可用，不能停留在代码层的“支持”，而要在页面里形成可点击、可恢复、可回流的实际链路。
- 各页面必须围绕同一个 `阅读会话` 工作，而不是各自独立。
- AI 只能增强，不应成为核心路径的唯一依赖。
- bug 风险要作为一等问题处理，尤其是导航参数、状态丢失、翻页手势、布局挤压和点击无效。

## 产品定位

### 1. 阅读中心

阅读中心是工具区中的统一阅读入口页，负责回答四个问题：

- 我现在最适合继续读什么？
- 我应该直接开始读，还是先进入专注？
- 我最近的阅读节奏怎么样？
- 我读完之后能去哪里继续复盘？

阅读中心的定位不是“再放四个入口”，而是统一承接这组能力的首页。

### 2. 沉浸阅读

沉浸阅读是阅读中心的主战场，承担：

- 正文阅读
- 目录跳转
- 阅读进度恢复
- 书签和重点标记
- 主题、字体、暖光、夜间模式切换
- 一键切换到专注模式
- 一键进入读后复盘

### 3. 专注模式

专注模式不再是独立计时器，而是“围绕当前阅读内容的专注层”。

它要回答：

- 我是为了哪篇内容进入专注？
- 这次专注想完成什么？
- 时间到了之后，我要回到哪里？

### 4. 阅读复盘

现在的 `大纲视图` 要被重构为 `阅读复盘`。

它的核心任务不是堆分析卡片，而是帮助用户在读后快速看清：

- 这篇内容的结构是什么
- 哪几个段落值得回看
- 主题、情绪和高频词有什么特征
- 这篇内容和其他记录相比有什么变化

### 5. 阅读主题

现在的 `封面主题` 要升级为 `阅读主题` 或 `阅读空间主题`。

它不再只是抽象的封面设置，而要影响阅读页的真实视觉体验，包括：

- 页面底色
- 字体风格
- 强调色
- 阅读卡片预览
- 默认阅读空间

## 信息架构

### 1. 阅读中心首页

首页建议分成五块：

- `继续阅读`
  - 展示最近一次阅读内容、阅读进度、上次停留时间、预计剩余时间
  - 允许一键回到上次页码
- `今日推荐`
  - 基于最近阅读、最近新内容、未完成会话给出 2-3 个动作
  - 例如：继续昨天未读完的条目、开始一次 15 分钟专注阅读、回看一篇高情绪波动的旧日记
- `阅读能力入口`
  - 沉浸阅读 / 专注模式 / 阅读复盘 / 阅读主题
  - 每个入口不只是名字，还要带一句“为什么现在值得点进去”
- `最近会话`
  - 最近读过什么、专注过什么、最近一次读后复盘做了什么
- `阅读空间概览`
  - 当前默认主题、累计阅读篇数、最近专注次数、书签数量

### 2. 沉浸阅读页

沉浸阅读页建议结构：

- 顶部极简控制条
  - 返回
  - 目录
  - 主题
  - 书签
  - 专注模式
- 中部正文区
  - 更强的段落排版
  - 更高的行高和边距控制
  - 真正可用的左右滑动翻页
- 底部阅读条
  - 当前进度
  - 剩余阅读估算
  - 继续专注/进入复盘
- 辅助抽屉
  - 目录
  - 书签/重点段
  - 阅读设置

### 3. 专注模式页

专注模式页建议结构：

- 顶部显示当前阅读上下文
  - 当前条目标题
  - 当前进度
  - 本次目标
- 中心区域显示计时和环境
  - 倒计时
  - 背景音
  - 当前会话状态
- 底部显示专注后的动作
  - 返回阅读
  - 标记完成
  - 进入复盘

### 4. 阅读复盘页

阅读复盘页要从“分析台”收敛成三层：

- `结构层`
  - 大纲
  - 段落定位
  - 重点段落
- `理解层`
  - AI 标签
  - 高频词
  - 情绪曲线
- `对比层`
  - 同主题旧内容
  - 时间段变化
  - 导出或分享摘要

默认优先单篇内容，时间范围和全局主题分析要收在次级层，不要默认压到主界面。

### 5. 阅读主题页

阅读主题页建议结构：

- 当前主题真实阅读页预览
  - 不再展示泛化“封面卡”，而是展示真实阅读页缩略预览
- 推荐主题
  - 结合当前阅读习惯或最近内容推荐
- 预设主题
  - 分类筛选
- 自定义主题
  - 保留自定义，但交互更聚焦
- 默认主题与使用统计
  - 明确告诉用户“这个主题会应用到哪里”

## 核心联动关系

### 输入链路

- 从工具页进入阅读中心
- 从阅读中心进入沉浸阅读
- 从沉浸阅读进入专注模式
- 从沉浸阅读进入阅读复盘
- 从阅读主题返回沉浸阅读并立即看到视觉变化

### 状态链路

阅读中心四个页面必须共享一个统一的 `ReadingSession`，至少包含：

- 当前 `diaryId`
- 当前标题
- 当前页码或段落位置
- 最近阅读时间
- 当前主题
- 是否有进行中的专注会话
- 最近书签/重点段

### 输出链路

- 专注模式完成后返回沉浸阅读
- 沉浸阅读读完后进入阅读复盘
- 阅读复盘中点击重点段落可返回阅读定位
- 阅读主题应用后回到阅读页立即生效

## UI 与排版方向

第三大类的视觉方向默认采用 `高级杂志感`，但不脱离现有设计系统。

具体要求：

- 标题层级更鲜明，主标题、分组标题、说明文案要有明显节奏差
- 正文阅读区保持克制，避免按钮密度过高
- 使用更清晰的留白和卡片边距，而不是把统计和按钮全部塞满
- 阅读页默认正文排版要明显优于普通列表页
- 各页的提示文案要具体，避免空泛修饰
- 移动端单手操作区域要明确，减少顶部密集小按钮误触

## Bug 风险重点

第三大类在实现时必须重点防守以下问题：

- 翻页手势写了但实际不触发
- `diaryId` 或页码没有通过导航或会话状态真正传递
- 页面离开后阅读进度全部丢失
- 主题应用后只保存数据、不影响真实阅读页
- 专注模式开始、暂停、停止后状态不一致
- 读后复盘中点击定位段落无效
- 大屏/小屏布局比例失衡，出现内容挤压或滚动冲突
- 入口文案和页面真实能力不匹配，造成“看起来很强但不好用”

## 验收标准

- 工具页的阅读分区能被统一理解为 `阅读中心`，而不是四个散工具。
- 用户可以从阅读中心继续上次阅读，而不是每次重新开始。
- 沉浸阅读的翻页、目录、书签、专注切换都是真正可用的链路。
- 专注模式明确承接当前阅读内容，而不是脱离上下文的计时器。
- 阅读复盘优先支持单篇读后结构回看，并能定位回正文。
- 阅读主题能直接影响真实阅读页预览和默认阅读空间。
- 统一 `ReadingSession` 至少覆盖当前条目、进度、主题和专注上下文。
- UI、排版和操作密度相比现状有明显提升。
- AI 不可用时，核心阅读、专注、主题和基础复盘仍可继续工作。

## 非目标

- 这一阶段不重做整个日记编辑器。
- 不引入新的后端服务。
- 不新增复杂的社交或公开阅读能力。
- 不把全量文本分析做成独立 BI 系统。
