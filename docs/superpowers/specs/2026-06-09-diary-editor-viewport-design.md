# 日记编辑器视口与记录流程修复设计

## 目标

本次修复聚焦“记录日记”过程中的核心可用性问题，优先解决输入换行时的错误滚动、正文可见区域被截短、滚动条难以操作的问题，并同步修复已确认的脏状态误判、草稿恢复不完整、工具栏联动失效等问题。

## 问题归因

当前问题不是单一布局错误，而是三层逻辑叠加导致：

1. `EditorScreen.kt` 的纸张容器、WebView 和工具栏共同决定正文实际可见高度，但没有建立统一的“编辑器安全可视区”模型。
2. `editor.html` 里 Quill 的 `scrollToCursor()` 在普通输入、换行、恢复焦点、键盘显隐后都会主动滚动，而且判断条件过于激进，只要光标接近边缘就会滚。
3. Kotlin 侧把程序化内容注入与用户真实编辑混在一起，导致旧内容加载也会触发“已修改”和自动草稿。

最终表现为：

- 输入一行后即使未被遮挡，也会被强制滚动。
- 纸张背景看起来很大，但真正可编辑区域只有中间一部分。
- 右侧滚动条只覆盖局部高度，命中区域很差。
- 打开旧日记可能被误判为有修改。
- 仅修改心情/天气/标签/位置的草稿无法可靠恢复。

## 设计原则

### 1. Web 编辑器成为唯一正文滚动控制者

Compose 不再参与正文实时滚动。Compose 只负责：

- 稳定地给 WebView 提供完整可用高度。
- 告知 WebView 当前底部安全区高度。
- 在键盘、工具栏、面板切换时提供离散状态，而不是持续推挤正文。

WebView 内只保留一套滚动规则：

- 仅当光标真实离开安全可视区时才滚动。
- 普通输入和换行默认使用“最小滚动”。
- 恢复焦点、插图后恢复等场景可显式使用“强制对齐”。

### 2. 让可编辑区域覆盖整张纸面

纸张容器和 WebView 必须共享同一个完整高度区域。正文滚动区域应覆盖整个纸面内容区，而不是视觉上是整张纸、实际只有中间一小块可滚动。

配套要求：

- WebView 填满纸张容器。
- `.ql-container` 和 `.ql-editor` 都以父容器高度工作。
- 滚动条跟随整个正文高度，不再出现只有局部可拖动的问题。

### 3. 区分程序性内容加载与用户编辑

加载已有日记、恢复草稿、应用模板时，不应触发“用户已编辑”状态，也不应立刻启动内容自动草稿。

需要在 Web 和 Kotlin 两侧建立“静默加载保护”：

- JS 标记当前是否为程序化设置内容。
- Kotlin 在加载完成前不把内容变化当作脏修改。

### 4. 草稿恢复按“有意义内容”判断

草稿恢复不能只看正文文本，应按完整编辑快照判断，只要标题、正文、心情、天气、标签、位置任一项有意义，就允许恢复。

### 5. 工具栏手动控制可恢复

手动显示/隐藏工具栏可以暂时覆盖自动逻辑，但不能永久锁死整场编辑会话。需要允许在明确场景下重新回到自动联动状态。

## 方案

### A. `editor.html`

- 重构根布局，使 `html/body/#editor/.ql-container/.ql-editor` 基于 100% 高度工作。
- 优化 `.ql-editor` 的右侧内边距与滚动条宽度，提升滚动条命中面积。
- 增加 `isProgrammaticChange` 与 `pendingSilentRestore` 标记。
- 重写 `scrollToCursor()`：
  - 使用编辑器真实 `clientHeight` 与底部安全区计算“安全可视区”。
  - 正文仍在安全区内时直接不滚。
  - 换行/普通输入使用 `behavior: auto` 的最小位移，避免每次都平滑滚动。
  - 仅恢复焦点、插图完成、键盘消失后校准时允许强制对齐。
- `setContentBase64()`、`setTemplate()`、草稿恢复时走静默流程，不向 Kotlin 报“用户编辑”。

### B. `EditorScreen.kt`

- 稳定纸张容器高度，避免纸张背景与 WebView 有效高度脱节。
- 放宽滚动条可触达区域，不再让外围裁切造成“滚动条贴边不可摸”。
- 把工具栏留白切换为更贴近真实 UI 的固定档位。
- 增加“加载旧内容/草稿期间忽略脏状态”的 Compose 保护。
- 标题、心情、天气、标签、位置变化时，纳入统一脏状态/草稿判断，不再只依赖正文版本号。
- 手动显隐工具栏后，在重新聚焦编辑器或明确恢复自动模式时解除锁定。

### C. `EditorUtils.kt`

- 扩展 `resolveEditorBottomGap()`，使其反映真实工具栏占位。
- 调整 `shouldRestoreDraft()`，基于 `EditorSnapshot`/有意义草稿判断。
- 补充纯逻辑测试入口，方便回归验证。

## 验证目标

修复后应满足：

1. 输入一行或普通换行时，只要光标仍在可视安全区内，页面不发生多余滚动。
2. 正文可编辑区域覆盖整张纸面内容区，右侧滚动条可沿整段内容正常拖动。
3. 打开已有日记后，未编辑直接返回，不应误弹未保存提示。
4. 仅修改元数据并退出保存草稿，下次进入仍能恢复。
5. 工具栏手动显隐不会把后续联动永久锁死。
