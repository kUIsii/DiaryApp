route 中文实施版路线图

这份不是“继续解释文档”，而是直接告诉你 DiaryApp 接下来该怎么优化。

这份页面只围绕最适合你当前 APP 的 4 份文档来重组内容： 详情页重设计、首页与日历重设计、时间线与回顾重设计、备份安全统计重设计。 我把它们从“资料”重新整理成“实施路线图”，按现在可做、中期适合做、以后再说拆开，并补上功能项、风险点和推荐落地方式。

核心原则很简单：所有建议都必须服务于你现在这款 App 的真实方向，也就是 日记核心体验优先、保持轻盈、增强记忆感、提升可靠性， 而不是为了“功能多”去做大而散的系统。

这份路线图的核心判断

1. 不再做“资料阅读”层面的整理

这次只讨论对当前 APP 真正有实施价值的方向，不再停留在解释文档内容。

2. 先解决高频体验问题，再做增强

编辑、阅读、回顾、首页表达、备份可靠性，这些比大重构和大扩展更值。

3. 所有扩展都不能破坏“日记核心”

如果一个方向会让 APP 变得分散、复杂、维护成本暴涨，那它现在就不该优先。

阶段分类标准

立即可做 中期适合做 以后再说 作为参考保留

“立即可做”不代表最简单，而是指：对当前 APP 提升最大，且投入风险可控。 “以后再说”也不代表没价值，而是说明它现在的时机不对，或者工程代价过高。

实施原则

在开始列功能前，先把策略讲清楚。因为同一份文档里往往既有适合现在做的，也有暂时不该碰太深的内容。

center_focus_strong

原则一：先做“每天都会碰到”的体验

优先处理编辑、预览、详情阅读、首页日历、回顾入口、备份恢复这些高频路径。因为这些问题一旦不顺，用户每天都会感知到。

  • 详情页、首页、时间线、备份都属于高频使用或高信任模块。
  • 这类优化比“新功能很多”更能让用户觉得 APP 真的在变好。
construction

原则二：优先做低风险、独立可发布的改进

每个阶段都尽量选择“单独做完就能提升体验”的功能块，避免所有事情耦合成一次大重构。

  • 例如分享、阅读模式、摘要卡、回收站自动清理、备份通知都适合独立推进。
  • 像编辑器整体迁移、完整云同步、复杂标签系统则不适合现在打包做。
balance

原则三：增强记忆感，但不要把 APP 做散

你的 APP 最适合继续强化“回顾、情绪、纪念、私人记录”的价值，而不是快速扩成庞杂的生活管理器。

  • On This Day、时间线回顾、图片管理、情绪统计都很贴这个方向。
  • 完整 Todo/Habit 大重构、复杂知识组织、云平台化则暂时不该抢主线。

第一阶段：立即可做

这一阶段的标准是：直接提升当前 APP 的核心体验，风险相对可控，而且做完一项就能感知到价值。

1

先把“读、看、回顾、备份”这些关键链路做顺

适合最近一到两个大版本持续推进，尽量拆成独立可发布的小块
当前最推荐 风险可控 最贴真实使用

详情页增加分享入口与分享面板

高价值

当前详情页已有部分分享/导出能力，但入口不清晰。这个改动不触底层结构，却能显著提升“日记内容可带走、可纪念、可传播”的感知。

来源：详情页文档 建议阶段：立即做 预估：1-2 天
展开看实施建议与风险点击展开

推荐落地方式： 在详情页底部操作栏加入明确的分享按钮，弹出底部面板，分为文字分享、图片分享、Markdown/导出入口。

  • 先做清晰入口和基础预览，不必一开始就做复杂模板系统。
  • 优先保证和现有详情页风格一致，避免另起一套设计语言。

风险点： 分享逻辑可能和现有导出逻辑耦合，需要先梳理 ViewModel 接口，避免 UI 加好了但行为不统一。

详情页阅读模式

高价值

这项不是炫技，而是让“查看日记”从普通页面变成更舒服的阅读体验，尤其适合长日记、晚间阅读和回顾场景。

来源：详情页文档 建议阶段：立即做 预估：1-2 天
展开看实施建议与风险点击展开

推荐落地方式： 先做最核心的 3 项：即时主题生效、字体大小调节、沉浸式阅读开关。先别把它设计成一个过大的系统。

  • 最值得优先解决的是深色模式闪动与字体无法就地调整的问题。
  • 阅读模式入口可以放在顶部工具栏，不要藏太深。

风险点： WebView 和 Compose 状态同步要稳定，避免切换模式时出现闪烁、布局跳变或设置不持久。

首页加入摘要卡与 On This Day 卡片

高价值

这是最适合立刻提升首页价值的一项。比起直接大改首页结构，先把“周摘要”和“往年今日”放到首页，是更稳也更有感知的路线。

来源：首页文档 建议阶段：立即做 预估：2-4 天
展开看实施建议与风险点击展开

推荐落地方式： 先不大改数据层，只调整首页组织方式。把周摘要放上面，把 On This Day 作为条件显示卡插在日历和当日列表之间。

  • 这是文档中建议的低风险首个 PR 方向，也很适合你的节奏。
  • 如果做得好，首页会立刻更像“日记入口”而不是“日期加列表”。

风险点： 首页信息变多后容易挤，所以要注意默认折叠与信息密度，不能一股脑堆成仪表盘。

首页卡片长按菜单与滑动操作

高价值

这类操作增强不会改变你的产品方向，但能明显改善“管理日记”的效率，包括收藏、删除、分享、进入多选等。

来源：首页文档 建议阶段：立即做 预估：2-4 天
展开看实施建议与风险点击展开

推荐落地方式： 先做长按菜单，再做轻量滑动操作。长按可以作为统一的高级入口，滑动只保留最常用的 1-2 个动作。

  • 推荐优先保留收藏和删除/移入回收站，避免手势过多。
  • 长按菜单可以顺便成为未来多选模式入口。

风险点： 首页已有点击跳详情、滚动等交互，新增滑动后要注意误触和动画层级。

回收站自动清理 + 只读预览

高价值

这是非常现实的“可靠性补强”。当前回收站如果只是显示 30 天文字而不自动清理，或者删前无法确认内容，就会显得逻辑不完整。

来源：时间线文档 建议阶段：立即做 预估：1-2 天
展开看实施建议与风险点击展开

推荐落地方式： 用 WorkManager 实现每日自动清理过期回收站条目，同时允许点开回收站卡片进入只读详情页预览。

  • 先做自动清理和预览就已经非常有价值，不必马上上批量操作。
  • 这会明显提升“删除之后我仍然放心”的安全感。

风险点： 真删逻辑如果联动图片、附件或标签，要先梳理清理范围，避免数据库删了但文件没删，或者反过来误删。

备份管理底座：自动备份、加密、失败可见

高价值

对私人日记来说，这一组能力的重要程度甚至高于很多视觉优化。它决定了用户敢不敢长期把内容放在你的 APP 里。

来源：备份安全文档 建议阶段：立即做 预估：6-9 天
展开看实施建议与风险点击展开

推荐落地方式： 第一批只做 3 件事：WorkManager 调度自动备份、备份文件加密、备份失败明确通知。先把本地备份可靠性打牢。

  • 不要一开始就冲云备份，那会把复杂度拉高很多。
  • 你的“备份管理”界面也应该以这 3 项为基础展开。

风险点： 自动任务在不同 ROM 的执行稳定性要验证；加密要考虑密钥管理；失败通知要避免骚扰但也不能静默吞掉异常。

锁定超时设置 + 基础隐私增强

中高价值

这类功能不是最显眼，但特别符合日记类 APP 的信任属性。尤其锁定超时非常实用，能降低频繁解锁带来的烦躁感。

来源：备份安全文档 建议阶段：立即做 预估：2-3 天
展开看实施建议与风险点击展开

推荐落地方式： 优先支持锁定超时、`FLAG_SECURE` 隐私保护、PIN 加盐存储。先把隐私体验做得“够用而稳”。

  • 锁定超时是对高频使用最友好的安全改良。
  • FLAG_SECURE 的收益很直接，投入也小。

风险点： 安全设置影响全局使用体验，必须保证状态同步一致，避免“明明设了却没生效”这类信任问题。

第二阶段：中期适合做

这一阶段适合在第一阶段核心体验更稳之后推进，主要用于增强“内容积累后的体验”和“长期使用的舒适度”。

2

增强“记忆感”和“长期使用体验”

适合在当前核心链路稳定之后持续推进，让 DiaryApp 更像一个会陪伴积累的产品
中期主力 提升记忆价值 开始涉及数据层优化

首页搜索与筛选升级

中高价值

当日记越来越多时，首页如果仍然只能点日期看列表，效率会开始下降。这个阶段可以逐步把搜索、筛选和排序能力移到首页主场景。

来源：首页文档 建议阶段：中期 预估：4-8 天
展开看实施建议与风险点击展开

推荐落地方式： 先做筛选面板，再做 FTS5。也就是说，先把 UI 交互模式跑通，再升级搜索引擎和数据层。

  • 这样做更稳，也便于逐步验证用户是否真的需要复杂搜索。
  • FTS5 非常值得做，但它已经触及数据库迁移，不建议和太多 UI 改动一起上。

风险点： 数据库迁移、搜索高亮、筛选条件叠加的组合复杂度会明显上升。

时间线分页 + 月份快速跳转 + 月摘要卡

高价值

当内容数量开始增多时，这一组功能会决定时间线还是否好用。它是“积累多了之后”的真正体验拐点。

来源：时间线文档 建议阶段：中期 预估：2.5-4 天
展开看实施建议与风险点击展开

推荐落地方式： 先做 Paging 和月份快速跳转，再补月摘要卡和视觉精修。顺序不要反过来。

  • 先解决性能和导航问题，用户最能感知。
  • 月份摘要卡是锦上添花，但也很适合你产品的回顾气质。

风险点： Timeline 逻辑和分组展示耦合度高，Paging 引入后，分组和分隔符要重新梳理。

图片管理体系：压缩、缩略图、全局图库

高价值

如果你的日记里会放图片，这组能力会越来越重要。它不是“附加功能”，而是稳定性、存储、回顾体验三者交汇的关键模块。

来源：时间线文档 建议阶段：中期 预估：3-4 天
展开看实施建议与风险点击展开

推荐落地方式： 顺序应该是：先压缩与缩略图，再做文件清理，最后做全局图库。不要先做图库再补底层。

  • 先稳住存储和性能，再做“好看、好逛”的相册体验。
  • 图片一多之后，全局图库会非常有记忆价值。

风险点： 图片处理容易引入文件残留、缩略图失效、迁移兼容等问题，必须把文件生命周期管理清楚。

导出增强：PDF / HTML / 选择性导出

中高价值

导出能力很适合日记产品，因为它会增强“内容属于我”的感觉。尤其 PDF 和 HTML，在纪念感和可迁移性上都很实用。

来源：详情页文档 + 备份文档 建议阶段：中期 预估：4-7 天
展开看实施建议与风险点击展开

推荐落地方式： 优先 PDF 和 HTML，先不要急着把 DOCX 做成正式格式。PDF 可用于留存，HTML 可用于开放查看，已经很够用。

  • 详情页导出和全局导出要尽量统一体验，不要两套规则。
  • 选择性导出更适合在收藏、时间线或备份管理里延伸。

风险点： WebView 导出和内容样式一致性、长内容分页、图片带入等都需要验证。

年热力图与轻量统计增强

中高价值

统计页最怕做得很重却没有感情。对你来说，更合适的是让统计页服务“回顾自己”，而不是变成分析后台。

来源：备份安全文档 建议阶段：中期 预估：5-8 天
展开看实施建议与风险点击展开

推荐落地方式： 优先做年热力图、月度柱状交互、基础心情趋势。先让用户一眼看懂自己写了多少、什么时候写、情绪大致如何变化。

  • 年热力图是高感知且很符合日记产品的统计表达。
  • 不要一开始就追求非常多图表类型，否则容易做重。

风险点： 图表太多会让页面显得像分析面板，反而削弱 DiaryApp 的情绪温度。

On This Day 进阶版：通知、Widget、Memory Lane

中高价值

这组功能非常有“陪伴感”，但应该放在首页内嵌卡做好之后再继续推进。否则会变成一个很美但用户接触不到的功能群。

来源：时间线文档 建议阶段：中期 预估：4 天左右
展开看实施建议与风险点击展开

推荐落地方式： 顺序应该是：先首页卡片，再通知，再 Widget，最后才是更偏仪式感的 Memory Lane 模式。

  • 这样用户能先理解这个功能，再接受它变成主动提醒。
  • Memory Lane 很有感觉，但一定不要早于基础入口建设。

风险点： 通知打扰、Widget 维护成本、Memory Lane 场景频率偏低，这些都需要靠使用频率验证。

第三阶段：以后再说

这些方向不是没价值，而是当前时机不对，或者成本与风险暂时不划算。保留想法可以，但不建议近期抢主线。

当前 APP 的优化方向地图

如果从“继续优化当前 APP”而不是“继续研究文档”的角度看，接下来最直接的方向大概就是下面这 6 类。

article

1. 阅读体验升级

包括阅读模式、分享、导出、图片查看、详情页展示一致性。这些方向最容易直接提升“这篇日记看起来舒服不舒服”。

calendar_month

2. 首页变成真正入口

让首页承担摘要、回顾、搜索入口和日历表达，而不是只当一个日历上面加当天列表。

history

3. 时间线更适合积累型使用

当用户有几百篇之后，时间线是否还能顺手看，是产品成熟度的重要体现。

backup

4. 备份与恢复建立信任

自动备份、加密、失败可见、恢复稳定，是私人日记 APP 的信任底层。

query_stats

5. 统计服务“回顾自己”

统计不该只为炫图表，而该帮助用户理解自己的记录频率、时间和情绪变化。

security

6. 隐私与安全保持克制但可靠

锁定超时、隐私模式、PIN 增强这些功能看起来不显眼，但会影响用户是否愿意长期依赖你。

几个非常重要的取舍提醒

这些提醒是我觉得最值得你明天重点看的部分，因为它们决定了后面是否会走弯路。

warning

不要因为编辑器问题，就马上跳到大迁移

现在这份路线图故意没有把“换编辑器”放进主线，是因为当前更值得先稳定外围体验和日记主流程。

moving

尽量做“独立可发布”的小步升级

比如分享、阅读模式、回收站预览、摘要卡，这些单项做完就能发布，不需要等大版本打包。

favorite

DiaryApp 最值得强化的是“记忆价值”

也就是回顾、情绪、纪念、私密、安全感。只要记住这一点，很多要不要做的选择都会变简单。

最终建议

如果把后续优化压缩成三个层级，我建议这样理解就够了。

现在就该做

  • 详情页分享入口
  • 详情页阅读模式
  • 首页摘要卡和 On This Day 卡片
  • 首页长按 / 滑动操作
  • 回收站自动清理和只读预览
  • 自动备份、加密、失败通知
  • 锁定超时和基础隐私增强

稳定后继续做

  • 首页搜索和筛选升级
  • 时间线分页与月份跳转
  • 图片压缩、缩略图、图库
  • PDF / HTML / 选择性导出
  • 年热力图和轻量统计
  • On This Day 通知 / Widget / Memory Lane

暂时别急

  • 详情页左右滑动切换文章
  • 首页全量分页和重型数据层重构
  • 云备份 / 增量备份 / SQLCipher 整体升级
  • 复杂统计和大仪表盘
  • 任何会让 APP 快速“做散”的扩展

如果你明天看完觉得这份路线图方向对了，最自然的下一步就是： 把“现在就该做”的这一组，再继续拆成真正的开发清单，按照版本节奏排序，比如 `v1：阅读与首页增强`、`v2：回收站与备份稳定`、`v3：时间线与图片体系`。
